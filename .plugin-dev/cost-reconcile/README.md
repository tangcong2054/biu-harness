# 造价三方对账（cost-reconcile）

页面里插一块。**跨表 join 是执行，不是描述** —— 三张表按清单编码对齐：


| 表                         | 是什么                          |
| ------------------------- | ---------------------------- |
| `cost_demo.t_cost_item`   | 合同清单（合同量 × 合同单价）             |
| `cost_demo.t_cost_change` | 签证变更（量增减 / 价增减，有 change\_id） |
| `cost_demo.t_settlement`  | 结算（结算量 × 结算单价）               |


对齐后逐条算 **差额 = 结算 − （合同 + 签证）**，并按偏差判定「一致 / 结算偏高 / 结算偏低 / 超支」。

- 选项目 → 「重新对账」，上面四张卡是汇总，下表是逐子目明细。
- 下面表单填一条签证（编码 / 类型 / 量增减 / 价增减 / 事由）→ 「写入这条签证」
→ **真 INSERT 进 `t_cost_change`**，并且返回**写入前 vs 写入后的差异对比**
（差异条数、差异绝对值、这个子目的差额怎么变的）。
- 「把 N 条差异写成结论」→ **真写 `cost_demo.t_cost_diff`**（子目 / 合同 / 变更后 / 结算 / 差额 / 偏差 / 原因 / 确认人）。
- 底部材料信息价对照（本市 vs 邻市，价差百分比）也是真算的。

**真实结果**：5 个项目各 5 个子目，4 个项目各 1 条差异 —— 临港物流园砖基础 **+8,531.83（8.98%）**、
滨江商务中心现浇构件钢筋 **+8,205.67（4.04%）**、高新人才公寓矩形柱混凝土 **+4,761.60（6.60%）**、
环城路改扩建平整场地 **+362.79（3.73%）**；城西医院住院楼三方一致。

**签证一变、差异立刻重算（实测）**：环城路平整场地补一条「量增 80」→ 差额从 `+362.79` 变成 `-371.61`（由偏高转偏低）；
再补一条「钢筋价调 +260 元/t」→ 差异从 1 条变 2 条，合计 10,301.01 元。

- 默认库：`127.0.0.1:3306 / root / cost_demo`。
- 写操作白名单：**只有 `t_cost_change` 和 `t_cost_diff`**；对账 SQL 是插件里写死的模板，
外部只能传项目 id，**不能传 SQL**。
- 坑（真踩过）：清单编码是 `010101001` 这种前导零串，当数字处理会丢前导零、join 直接对不上 ——
字面量转义里对这种情况强制当字符串。
- 数据接口：`GET /api/cost-reconcile/projects|reconcile|changes|diffs|material`、
`POST /api/cost-reconcile/change|write-diff`。无头插件，没有窗口。
