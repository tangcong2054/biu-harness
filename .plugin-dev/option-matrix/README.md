# 方案对比块（option-matrix）

在页面文档里插入一个**多方案 × 多维度**的加权对比矩阵：填方案、填维度、给权重和打分，块会**实时算加权总分并排出推荐**。

- **越低越好的维度会反向计入**：维度上可切 `↑越高越好` / `↓越低越好`。标成「越低越好」的维度（比如开发成本），打分越高代表越差，算总分时会换成 `满分+1 − 原分` 再加权（表格里会显示 `→反向分`）。这是这个块和「简单求和」最大的差别。
- 实时计算：改权重、改分数、加方案、加维度，总分、百分比、推荐标记立刻变。
- 每个维度的最优格高亮（越高越好取最大、越低越好取最小，归一化后都是最大）。
- 底部自动生成一句「为什么推荐它」，把各维度最优项拼起来。
- 点「导出 Markdown」可把矩阵导出成 markdown 表格（带权重、方向、反向分），直接给 agent 读。

## 三种看法：矩阵 / 卡片 / 排名

维度一多，一张宽表就挤成一团。块头部的分段控件可以随时换看法（**只读态也能切**，纯看的人不用改数据）：

| 看法 | 长什么样 | 什么时候用 |
|---|---|---|
| `matrix` 矩阵 | 方案 × 维度一张表，**表头吸顶、方案列与总分裂吸左/吸右**；正文里最多 330px（紧凑 260px）就出现内部滚动，不撑爆页面 | 维度少（<6）或要逐格改分数 |
| `cards` 卡片 | 一个方案一张卡：排名、加权总分、总进度条，下面每个维度一行（名称 + 权重/方向 + 分数 + 条形），最优项高亮 | 维度多、要一次看清每个方案的全貌 |
| `rank` 排名 | 只留结论：三个方案按加权总分排序的横条 + 每个维度最优归属的 chip | 汇报 / 结论页，一眼看谁赢 |

不写 `view` 时按规模自动挑：**维度 ≥ 6 或 方案×维度 ≥ 16 → 卡片，否则矩阵**。

其余两个呈现开关：

- `density`：`comfortable` 舒适（默认）/ `compact` 紧凑（字更小、留白更少，适合宽度紧张或维度多）。
- `foldMinor`：`true` 时**只显示权重不低于平均值的维度**，头部按钮会写「只看高权重（-N）」，点一下切回「显示全部维度（+N）」。推荐句也跟着折叠走，只讲还在台上的维度。

## 放大：全屏看整张矩阵

头部「⤢ 放大」把整块提升成一个铺满视口的覆盖层（`createPortal` 到 body，**不搬 DOM，放大后照样能切视图、改分数**），并顺带申请浏览器全屏；按 **Esc** 或点「⤡ 缩小」退出。放大态下矩阵不再限制高度、字号也放大一档，几十格也不挤。

## 示例写法

```md
:::pageBlock {kind=option-matrix plugin=option-matrix id=b7e24f19}
{
  "title": "登录方案选型",
  "scale": 5,
  "view": "cards",
  "density": "comfortable",
  "options": ["手机号+验证码", "微信一键登录", "账号密码"],
  "criteria": [
    { "name": "开发成本", "weight": 3, "higherIsBetter": false },
    { "name": "安全性", "weight": 5, "higherIsBetter": true },
    { "name": "转化率", "weight": 5, "higherIsBetter": true }
  ],
  "scores": {
    "手机号+验证码": { "开发成本": 4, "安全性": 4, "转化率": 4 },
    "微信一键登录": { "开发成本": 3, "安全性": 4, "转化率": 5 },
    "账号密码": { "开发成本": 5, "安全性": 2, "转化率": 2 }
  }
}
:::
```

可写字段：`title`（标题）、`scale`（满分制，默认 5）、`options`（方案名数组）、`criteria`（`{name, weight, higherIsBetter}`）、`scores`（`方案 → 维度 → 分`）、`view`（`matrix` / `cards` / `rank`）、`density`（`comfortable` / `compact`）、`foldMinor`（布尔）。

> `view` / `density` / `foldMinor` 是「看的人」的选择：只读态切换只影响本机显示；可写态切换会顺手记进块数据，下次打开还是这个看法。

## 算法

```
归一化分 = higherIsBetter ? 原分 : (scale + 1 − 原分)
加权总分 = Σ( weight × 归一化分 )
满分     = Σ( weight × scale )
推荐     = 总分最高者（并列时按方案名）
```

## 自测（可选）

`verify.mjs` 不依赖浏览器的算法自测：把打包后的 web 渲染成静态 HTML（react-dom/server），断言加权总分、反向计入、改权重/翻转维度方向后结论会变。

```sh
# 1) 复刻宿主打包方式，产出 /tmp/omverify/web.mjs（react/react-dom 走宿主 globalThis）
node /tmp/omverify/build.mjs
# 2) 跑原自测（补上 globalThis.ReactDOM 占位）
node /tmp/omverify/run-verify.mjs
```

预期输出以 `ALL PASS ✅` 结尾。默认样例三个方案的加权总分分别是 46.0 / 54.0 / 23.0（满分 65.0），推荐「微信一键登录」；若写成简单求和会是 12 / 12 / 9（前两名并列，推不出结论）——这就是反向计入的价值。
